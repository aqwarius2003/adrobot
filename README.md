# Keitaro Campaign Manager

Веб-приложение для создания и редактирования рекламных кампаний в Keitaro.
Backend: FastAPI + SQLAlchemy. API-ключ проверяется сервером и остаётся на сервере.

## Какой запуск выбрать

Для проверки с настоящим Keitaro выберите **один из двух основных способов**:
Python/uv, если удобнее запускать приложение напрямую, или Docker Compose, если
Docker уже установлен. Оба способа запускают Creator и Editor без demo-функций.

| Что проверяем | Без Docker | С Docker |
| --- | --- | --- |
| Настоящий Keitaro, нужен адрес трекера и API-ключ | [Вариант 1](#keitaro-python) | [Вариант 2](#keitaro-docker) |
| Автономная демонстрация без доступа к Keitaro — необязательно | [Вариант 3](#demo-python) | [Вариант 4](#demo-docker) |

Отдельный сервер базы данных не нужен ни в одном варианте. SQLite-файлы и
миграции подготавливаются автоматически. `APP_ENV=development` разрешает
локальный HTTP и **не включает demo**.

Достаточно одного варианта. Все они используют порт 8000: перед сменой способа
остановите предыдущий процесс или Compose.

## Запуск с настоящим Keitaro

Для обоих основных способов сначала скачайте проект:

```bash
git clone https://github.com/aqwarius2003/adrobot.git
cd adrobot
```

Создайте в папке проекта файл `.env`:

```dotenv
KEITARO_BASE_URL=https://tracker.example
APP_ENV=development
DEMO_ENABLED=false
```

Замените `https://tracker.example` корневым адресом вашего трекера, без `/admin`
и `/admin_api/v1`. API-ключ в файл добавлять не нужно.

<a id="keitaro-python"></a>

### 1. Без Docker: Python и uv

Нужны Git, Python 3.11+ и uv. Docker устанавливать не требуется.

```bash
uv sync --locked
uv run --locked uvicorn src.main:app --host 127.0.0.1 --port 8000
```

Оставьте терминал открытым. Для остановки нажмите `Ctrl+C`. Рабочие данные
сохраняются в папке `data/` проекта, включая личные черновики в `data/real_keys/`.

<a id="keitaro-docker"></a>

### 2. С Docker Compose

Нужны Git и запущенный Docker с Compose. Python и uv на компьютере не требуются.

```bash
docker compose up -d --build
```

Контейнер доступен только на `127.0.0.1:8000`. Рабочие данные сохраняются в Docker
volume `adrobot_persistent_data`. Это отдельное хранилище: локальная папка `data/`
из варианта 1 в него автоматически не переносится.

Проверка и остановка:

```bash
docker compose ps
docker compose logs --tail=50 web
docker compose down
```

Остановка без `-v` сохраняет данные.

### После запуска любым основным способом

Откройте [страницу входа](http://127.0.0.1:8000/login) и введите свой API-ключ.
После входа доступны «Создание кампании» и «Редактор ADROBOT».

Черновики, Baseline, архив и pins хранятся локально на backend. При первом входе
создаётся отдельная БД черновиков для вашего подключения и ключа. Отдельно
настраивать БД, выполнять миграции или загружать начальные данные не нужно.

[Health check](http://127.0.0.1:8000/api/health) должен вернуть `status: ok` и
`database: connected`. Это проверяет backend и его БД; доступность и права ключа
Keitaro проверяются при входе.
После перезапуска сервера потребуется снова войти; черновики сохраняются.

## Возможности

**Campaign Creator** создаёт кампанию с выбранными доменом, группой и источником,
ротацией по позиции и двумя потоками:

- Flow 1: выбранные GEO → HTTP redirect на Google.
- Flow 2: остальные посетители → выбранные офферы с целыми долями общей суммой 100%.

Название используется без автоматического префикса, пробелы по краям удаляются.
Перед записью проверяется уникальность имени без учёта регистра. Результат
подтверждается отдельным чтением созданных объектов.

**Campaign Editor** загружает кампанию через Fetch Streams. Add, Remove,
Bring back, Pin, изменение веса и Cancel сохраняются локально. Push to KT
публикует только выбранный поток, проверяет внешний конфликт до записи и
подтверждает результат отдельным чтением. Removed не удаляет глобальный оффер.
Cancel восстанавливает черновик потока из Baseline вместе с весами и pins.

В поле выбора кампании можно искать по ID или нескольким словам названия
без учёта регистра. Стрелки и Enter выбирают результат; Escape отменяет поиск.
Ввод текста сам по себе не переключает текущую кампанию.

Черновики разных ключей изолированы. Подтверждённое состояние и черновики
переживают перезагрузку страницы и перезапуск приложения.

## Публичное размещение

Для размещения на сервере задайте в `.env`:

```dotenv
KEITARO_BASE_URL=https://tracker.example
APP_ENV=production
DEMO_ENABLED=false
APP_SECRET_KEY=
```

Укажите настоящий HTTPS-адрес трекера и заполните `APP_SECRET_KEY` случайным
секретом длиной не менее 32 символов. Настройте HTTPS reverse proxy к локальному
порту 8000. Вход в production требует HTTPS; cookies используют Secure,
HttpOnly и SameSite=Strict. Настройте доверенные адреса proxy при необходимости.
Не открывайте development наружу. Используйте один Uvicorn worker: введённые
ключи хранятся в памяти процесса, а не в cookie или SQLite.

Секреты передаются при запуске, не входят в Docker image и не коммитятся.
Постоянный Docker volume необходим для сохранения данных при обновлениях.

## Дополнительно: демонстрация без доступа к Keitaro (+ DEMO режим)

Эти варианты нужны только для автономной проверки на синтетических кампаниях и
офферах. Они явно включают demo-функции: переключатель Keitaro/Демо и вкладку
симулятора. API-ключ настоящего Keitaro для демонстрации не требуется.

Для вариантов 3 и 4 также сначала скачайте проект командами `git clone` и `cd`
из начала инструкции.

<a id="demo-python"></a>

### 3. Демо без Docker: Python и uv

Нужны Git, Python 3.11+ и uv. Используйте такое содержимое `.env` вместо настройки
Keitaro выше:

```dotenv
APP_ENV=development
DEMO_ENABLED=true
KT_MODE=demo
DEMO_SIMULATOR_URL=http://127.0.0.1:8001
```

Запустите:

```bash
uv sync --locked
uv run --locked uvicorn src.main:app --host 127.0.0.1 --port 8000
```

Откройте [демо-редактор](http://127.0.0.1:8000/demo/editor). Симулятор запустится
автоматически на локальном порту 8001; отдельная команда для него не нужна.
Данные приложения и симулятора сохраняются в `data/`, отдельно от рабочих
черновиков Keitaro. Остановка всего приложения и встроенного симулятора — `Ctrl+C`.

Чтобы вернуться к варианту 1, остановите сервер и восстановите `.env` из раздела
«Запуск с настоящим Keitaro», включая `DEMO_ENABLED=false`.

<a id="demo-docker"></a>

### 4. Демо с Docker Compose

Нужны Git и запущенный Docker с Compose. Настройка `.env`, Python, uv и ключ
Keitaro не требуются: выбранный Compose-файл уже включает всё необходимое.

```bash
docker compose -f docker-compose.demo.yml up -d --build
```

Откройте [демо-редактор](http://127.0.0.1:8000/demo/editor). Симулятор работает в
отдельном контейнере внутренней сети Docker. Данные сохраняются в отдельном
volume `adrobot_demo_persistent_data` и не переносятся из локального варианта 3
автоматически.

Остановка с сохранением данных:

```bash
docker compose -f docker-compose.demo.yml down
```

## Настройки

| Переменная | Назначение | По умолчанию |
| --- | --- | --- |
| `KEITARO_BASE_URL` | Корневой URL трекера | `https://tracker.example` |
| `REAL_KEITARO_BASE_URL` | Необязательное переопределение URL трекера | Не задано |
| `APP_ENV` | `development` для локального HTTP; `production` для HTTPS | `development` |
| `APP_SECRET_KEY` | Секрет подписи сессий; обязателен в production | Локальное значение для разработки |
| `REAL_DATABASE_URL` | Рабочая SQLite, рядом с которой хранятся личные БД | `sqlite:///./data/app.db` |
| `SECURITY_DATABASE_URL` | Сессии и ограничения попыток входа | `sqlite:///./data/security.db` |
| `COMMIT_SHA` | Версия сборки для диагностики | `dev` |

Compose задаёт пути SQLite внутри `/app/data`; локальные файлы `.env` не входят
в образ. Настройки расширенного Python-запуска находятся в `.env.example`.

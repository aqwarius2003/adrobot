# Keitaro Campaign Manager (Creator & Editor)

Полнофункциональное веб-приложение — надёжная обёртка над Keitaro Admin API для создания и редактирования рекламных кампаний:
- **Campaign Creator (Часть 1)**:
  - Создание кампании с доменом, группой, источником и двумя потоками:
    - **Flow 1**: фильтр стран (`Country: accept [GEO]`) → HTTP redirect на `https://google.com/`.
    - **Flow 2**: `Default` fallback для остальных посетителей → выбранный оффер со 100% долей.
  - Имя без автоматического префикса, проверка уникальности в выбранном подключении, валидация ISO 3166-1 alpha-2, формирование Tracking URL с доменом и параметрами источника.
  - Пошаговая фиксация ID объектов и глубокая верификация маршрутизации.
- **Campaign Editor (Часть 2)**:
  - **Fetch Streams**: импорт потоков с merge по remote ID, сохранение локального архива, отображение потоков без офферов строкой (opaque stream). При внешнем удалении всех офферов поток сохраняется как управляемый, а офферы переводятся в `Removed` с 0% и возможностью `Bring back`.
  - **Draft & Персистентность**: локальное добавление (`Add`), удаление в архив (`Remove` с 0%), возврат (`Bring back`) и фиксация долей (`Pins`) без запросов на запись в Keitaro. Черновик переживает перезагрузку браузера и рестарт backend. Блокировка конфликтующих мутаций во время сетевых операций (`publishing`, `unknown`).
  - **Алгоритм распределения весов**: строгое поддержание суммы 100% среди активных офферов, детерминированное распределение остатка `divmod(100 - S_pinned, len(U))`, целые проценты, фиксация pinned-весов других офферов, запрет удаления последнего активного оффера.
  - **Cancel**: мгновенный откат черновика к последнему подтверждённому состоянию (Baseline).
  - **Push**: публикация только активных офферов выбранного потока (без removed и pins), preflight-сверка fingerprint с удалённым состоянием трекера, post-push верификация, pin-only оптимизация (пропуск лишнего PUT), reconciliation при timeout или сетевом сбое.

## Архитектура и поддерживаемая конфигурация

- **Поддерживаемая конфигурация задания**: строго один процесс приложения (`adrobot`) и один автономный экземпляр симулятора (`keitaro_simulator`).
- **Изоляция режимов**:
  - **Демо-режим** (`demo`): работает автономно с синтетическим каталогом симулятора, изолированной SQLite базой `data/demo_app.db` и встроенным сервером симулятора (`127.0.0.1:8001`). Не требует реального API-ключа Keitaro, сертификатов и настройки HTTPS.
  - **Боевой режим** (`real`): прямое подключение к рабочему Keitaro Admin API через backend с изолированной SQLite базой `data/app.db`. Вход защищён API-ключом (в роли пароля) с серверной сессией и защитой от перебора (rate limiting).
- **Разделение локального и публичного запуска**:
  - **Локальный запуск** (`APP_ENV=development`): обычный HTTP на `http://127.0.0.1:8000`. По умолчанию сервер слушает только локальный интерфейс (`127.0.0.1`). Вход в боевой режим по ключу доступен локально по HTTP.
  - **Публичное размещение** (`APP_ENV=production`): вход в боевой режим строго требует HTTPS. Включаются cookies с флагами `Secure; HttpOnly; SameSite=Strict`, валидация CSRF и проверка стойкости серверного секрета. Проверка TLS-сертификатов настоящего Keitaro всегда активна.

## Запуск приложения

### 1. Локальный запуск (по умолчанию)

1. Клонируйте репозиторий:
   ```bash
   git clone https://github.com/aqwarius2003/adrobot.git
   cd adrobot
   ```

2. Установите зависимости через `uv`:
   ```bash
   uv sync --locked --group dev
   ```

3. Подготовьте файл `.env` из примера:
   ```bash
   cp .env.example .env
   ```
   *По умолчанию в `.env.example` задан `KT_MODE=demo` и `APP_ENV=development`, что позволяет сразу запустить приложение без сторонних сервисов.*

4. Примените миграции базы данных:
   ```bash
   uv run --locked alembic upgrade head
   ```
   *Существующие базы данных SQLite автоматически и безопасно принимаются под управление Alembic с сохранением всех записей.*

5. Запустите сервер:
   ```bash
   uv run --locked uvicorn src.main:app --host 127.0.0.1 --port 8000 --reload
   ```
   *При старте бэкенд проверяет доступность симулятора на `http://127.0.0.1:8001/health` и при необходимости автоматически запускает автономный симулятор в фоновом потоке.*

- **Главная страница / Редактор**: [http://127.0.0.1:8000/](http://127.0.0.1:8000/)
- **Вкладка симулятора**: [http://127.0.0.1:8000/demo/simulator](http://127.0.0.1:8000/demo/simulator)
- **Проверка здоровья (Health Check)**: [http://127.0.0.1:8000/api/health](http://127.0.0.1:8000/api/health)

> [!NOTE]
> Если сервер приложения остановлен, открытая страница в браузере может оставаться видимой, но при выполнении действий (Fetch Streams, Push, Remove, Cancel) интерфейс отобразит понятное уведомление: **«Нет связи с приложением. Проверьте, что сервер запущен»**. Все локальные черновики сохраняются в базе данных SQLite и восстанавливаются после перезапуска сервера.

### 2. Запуск в Docker Compose

Для изолированного контейнерного запуска с персистентными томами:

```bash
docker compose -f docker-compose.demo.yml up -d --build
```

- Порт приложения привязан к `127.0.0.1:8000` (доступ только с локального компьютера).
- Симулятор работает в выделенном контейнере `adrobot-simulator` на внутренней сети Docker.
- Проверка состояния:
  ```bash
  docker compose -f docker-compose.demo.yml ps
  curl http://127.0.0.1:8000/api/health
  ```

## Режимы работы и единый интерфейс

Приложение работает в архитектуре **одного сайта и одного окна браузера**. В верхней панели навигации расположен переключатель режимов: **«Keitaro»** (боевой трекер) и **«Демо»** (симулятор).

### Политика режимов и изоляция данных

| Режим | Метка в шапке | Кнопка публикации | Доступные экраны | Хранилище (БД) | Upstream |
|---|---|---|---|---|---|
| **Keitaro (боевой)** | `Подключение: Keitaro` | `Push to KT` | Создание (`/real/creator`), редактор (`/real/editor`) | `data/real_keys/<scope>.db` | Боевой трекер Keitaro |
| **Демо (симулятор)** | `Демо · симулятор` | `Push to Demo` | Создание (`/demo/creator`), редактор (`/demo/editor`), Keitaro — симулятор (`/demo/simulator`) | `data/demo_app.db` | Автономный симулятор (`http://127.0.0.1:8001`) |

- **Первый вход**: При `KT_MODE=demo` сразу открывается демо-редактор. При переключении в боевой режим требуется ввести действующий API-ключ Keitaro на защищённой странице входа `/login`.
- **Изоляция сессий и ключей**: Запросы изолированы через `ConnectionContext`. Базы SQLite, ключи и сессии real/demo физически разделены. Выход из боевого режима или переход в демо отзывает сессию.
- **Вход по своему ключу**: сервер проверяет введённый ключ через `GET /admin_api/v1/campaigns` на настроенном трекере. Совпадение с `.env` не требуется. Все запросы сессии выполняются этим ключом. Ключ хранится только в памяти единственного процесса сервера, не в cookie или SQLite; после перезапуска нужно войти заново. Для такого запуска используйте один Uvicorn worker. Сессии, CSRF и ограничение попыток сохраняются.
- **Личные черновики**: real-данные разделены по закрытому отпечатку трекера и ключа в `data/real_keys/<scope>.db`; повторный вход тем же ключом возвращает его черновики. Схема каждого нового файла применяется Alembic. Общая legacy-БД сохраняется, но не выдаётся произвольному другому ключу.
- **Вкладка «Keitaro — симулятор»**: Доступна в демонстрационном режиме (`/demo/simulator`). Позволяет управлять удалённым симулятором Keitaro для воспроизведения внешних изменений, конфликтов версий и детекции удалённых офферов.
- **Создание кампании**: Доступно в обоих режимах. Поиск GEO принимает название страны на русском/английском или ISO-код; выбранные страны отображаются компактными кодами с подсказкой. Можно выбрать один или несколько существующих офферов. Создаются два потока: выбранные страны → Google, остальные посетители → выбранные офферы с общей долей 100%. В демо используются только синтетические офферы и состояние симулятора; новая кампания доступна в редакторе ADROBOT и во вкладке симулятора. В real действуют вход по ключу, CSRF и права самого ключа Keitaro. Демо-проверка не подтверждает доступность реальной записи.

## Переменные окружения (.env)

| Переменная | Описание | Значение по умолчанию |
|---|---|---|
| `KT_MODE` | Режим по умолчанию: `demo` (симулятор) или `real` (боевой KT) | `real` |
| `DEMO_SIMULATOR_URL` | URL сервиса симулятора в демо-режиме | `http://127.0.0.1:8001` |
| `KEITARO_BASE_URL` | Базовый URL Keitaro (для `KT_MODE=real`, без `/admin_api/v1`) | `https://tracker.example` |
| `KEITARO_API_KEY` | Необязательный legacy-ключ; посетитель вводит свой ключ при входе | *пусто* |
| `CAMPAIGN_SURNAME` | Фамилия в названиях стартовых демо-примеров; Creator не добавляет префикс | `rykov` |
| `APP_ENV` | Окружение: `development` (HTTP на 127.0.0.1) или `production` (HTTPS) | `development` |
| `APP_HOST` | Локальный интерфейс привязки сервера | `127.0.0.1` |
| `APP_PORT` | Порт сервера | `8000` |
| `DATABASE_URL` | URL SQLite базы данных по умолчанию | `sqlite:///./data/app.db` |
| `APP_SECRET_KEY` | Серверный секрет для подписи сессий и токенов | `dev-secret-key-change-in-prod` |
| `COMMIT_SHA` | SHA версии приложения | `dev` |

> [!IMPORTANT]
> Введённый ключ отправляется только на HTTPS-форму входа и не возвращается клиенту. Он не сохраняется в cookie, localStorage, SQLite или слоях Docker-образа. Браузер взаимодействует исключительно со своим FastAPI backend.

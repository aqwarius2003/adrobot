# Разработка и дополнительные инструменты

Обычный запуск описан в README и работает только с настоящим Keitaro.

## Автономный симулятор

Demo отключено по умолчанию. Для разработки без настоящего Keitaro используется
отдельная конфигурация, явно включающая `DEMO_ENABLED=true`:

```bash
docker compose -f docker-compose.demo.yml up -d --build
```

Откройте http://127.0.0.1:8000/. В этой конфигурации доступны Creator, Editor,
переключатель Keitaro/Демо и вкладка симулятора. Симулятор работает в отдельном
контейнере внутренней сети Docker; данные хранятся в отдельном persistent volume.
Для входа в Keitaro по-прежнему нужны настроенный URL и действующий ключ.

Запускайте только одну из конфигураций одновременно: они используют локальный
порт 8000. Остановка: `docker compose -f docker-compose.demo.yml down`.
Не добавляйте `-v`, если требуется сохранить данные.

Для локального Python-запуска укажите в отдельном локальном окружении:

```dotenv
DEMO_ENABLED=true
KT_MODE=demo
DEMO_SIMULATOR_URL=http://127.0.0.1:8001
REAL_DATABASE_URL=sqlite:///./data/app.db
DEMO_DATABASE_URL=sqlite:///./data/demo_app.db
```

После этого запустите Uvicorn командой из README. Локальный симулятор запускается
автоматически только при `DEMO_ENABLED=true` и стандартном локальном адресе.
Другой URL означает отдельный сервис; backend не запускает его автоматически.
Для real/demo сохраняется изоляция БД, ключей, операций и кэшей.

При `DEMO_ENABLED=false` переменная `KT_MODE=demo` и старые cookies не включают
demo: остаётся только Keitaro. Demo-настройки и файлы не используются и не
проверяются; ранее созданные файлы не удаляются.

## Проверки

```bash
uv sync --locked --group dev
uv run --locked ruff check .
uv run --locked ruff format --check .
uv run --locked pytest
```

Регрессионные тесты явно включают дополнительные инструменты и используют
временные каталоги. Проверки обычного старта выполняются в отдельных процессах
без этого флага: проверяют отсутствие импортов симулятора, его файлов и сетевых
запросов, закрытые маршруты, чистые страницы и миграции рабочей SQLite.

Frontend-проверки: запустите каждый `tests/test_frontend_*.js` через Node.js.
Проверки симулятора не подтверждают работу записи в настоящем Keitaro.
